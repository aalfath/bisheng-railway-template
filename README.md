# Bisheng on Railway

This repo packages [Bisheng](https://github.com/dataelement/bisheng) as a Railway template. Bisheng is an open-source platform for building LLM applications: knowledge bases (RAG), visual workflows, assistants and agents.

Every service is built from a folder of this repo. Each folder has a Dockerfile that pins the official upstream image by version and digest and adds only a small start script.

## What it deploys

| Service | Folder | Image | Role |
| --- | --- | --- | --- |
| **Bisheng** (public) | `frontend/` | `dataelement/bisheng-frontend:v3.0.1` | nginx serving the web UI. Proxies `/api` to the API and file links to RustFS |
| **Bisheng API** | `backend/` | `dataelement/bisheng-backend:v3.0.1` | FastAPI backend. Runs database migrations on start |
| **Bisheng Worker** | `backend/` (`BISHENG_ROLE=worker`) | same | Celery workers, Celery beat and the LinSight worker |
| **OpenFGA** | `openfga/` | `openfga/openfga:v1.19.0` | Permission engine. Stores its data in the MySQL `railway` database |
| **Elasticsearch** | `elasticsearch/` | `elastic/elasticsearch:8.19.25` | Keyword search for knowledge bases. Password auth, private network only |
| **Milvus** | `milvus/` | `milvusdb/milvus:v2.5.27` | Vector store. Standalone with embedded etcd and local storage on its volume |
| **RustFS** | `rustfs/` | `rustfs/rustfs:1.0.6` | S3-compatible storage for uploaded files (MinIO no longer publishes images) |
| **MySQL** | Railway database | Railway MySQL | Bisheng's database (`bisheng`) and OpenFGA's (`railway`) |
| **Redis** | Railway database | Railway Redis | Cache and Celery broker |

Volumes: MySQL, Redis, Elasticsearch (`/usr/share/elasticsearch/data`), Milvus (`/var/lib/milvus`) and RustFS (`/data`). The API and worker keep no data of their own.

## Variables

You don't need to fill in anything to deploy. All passwords are generated by Railway, and services find each other through reference variables.

| Service | Variable | Default | Notes |
| --- | --- | --- | --- |
| Elasticsearch | `ELASTIC_PASSWORD` | generated | Password of the `elastic` user. The API and worker read it by reference |
| RustFS | `RUSTFS_ACCESS_KEY` / `RUSTFS_SECRET_KEY` | generated | S3 credentials. The API and worker read them by reference |
| API and worker | `MYSQL_URL`, `REDIS_URL`, `OPENFGA_URL`, `ELASTICSEARCH_URL`, `MILVUS_HOST`, `S3_ENDPOINT` | references | Wiring to the other services |
| API and worker | `BISHENG_ROLE` | `api` / `worker` | Which processes the backend image runs |
| Bisheng (web) | `API_HOST`, `S3_ENDPOINT` | references | Where nginx proxies `/api` and file links |

## First login

Open the public URL of the **Bisheng** service right after the deploy finishes and register an account. **The first account registered becomes the super admin.** Bisheng has no default admin password, so do this before you share the URL. Passwords need at least 8 characters with upper- and lower-case letters, a digit and a symbol. Accounts registered after it get the default user role.

Then add a model provider (OpenAI, DeepSeek, Qwen, Ollama, …) under Models before you build knowledge bases or workflows. API keys go into Bisheng's UI, not into Railway.

## Not included

- The optional app runtime ("App Factory" hosted apps). It needs a Docker socket, which Railway doesn't provide. `/apps/…` shows Bisheng's "app runtime not enabled" page.
- The code-runner sandbox (`bisheng-sandbox`, used by the code interpreter tool). It needs Linux capabilities and a memory limit per session that Railway doesn't offer.
- The commercial gateway, OnlyOffice and the GPU model services (`bisheng-rt`, `bisheng-ft`).

## Updates

Railway sends deployers an "update available" notice when this repo's `main` branch changes. Each change bumps a pinned digest and adds an entry to [`CHANGELOG.md`](CHANGELOG.md), with breaking changes listed first. Read it before you apply an update. Database migrations run automatically when the API starts.

## Local test

Each folder builds with `docker build`. The start scripts expect the same variables as the template. See the table above and each folder's `railway-start.sh`.
